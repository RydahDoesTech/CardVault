# CardVault

CardVault is a **React Native (Expo) + TypeScript** app for cataloging trading cards. The MVP targets **Pokémon** with a service layer that can grow to other games. **Supabase** provides auth, Postgres, row-level security, and private file storage.

## Features (MVP)

- Email/password **sign up, sign in, sign out** with **persisted sessions** (AsyncStorage + Supabase).
- **Collection** list with search, condition filter, sort, totals, and pull-to-refresh.
- **Add card** flow: search (Pokémon TCG API or mock), pick a match, set condition, quantity, optional purchase price/notes, save to Supabase.
- **Card detail**: view/edit condition, quantity, purchase price, notes; **delete**; **refresh estimated value** (modular pricing providers; mock by default).
- **Scan** tab: take or pick a photo, **upload to Supabase Storage**, placeholder “OCR/identify” that reuses the search service, then confirm a match and continue in **Add** with the scan path attached.
- **Modular pricing** and **card search** providers for future APIs (TCGPlayer, eBay, etc.).

## Requirements

- **Node.js 20+** and **npm** (or **pnpm** / **yarn**).
- **Expo CLI** (via `npx`).
- A **Supabase** project.
- For physical devices: **Expo Dev Client** (this project is not limited to Expo Go because of native prebuild / dev client usage).

## 1. Clone and install

```bash
cd CardVault
npm install
```

Copy environment variables:

```bash
cp .env.example .env
```

Edit `.env` and set:

- `EXPO_PUBLIC_SUPABASE_URL`
- `EXPO_PUBLIC_SUPABASE_ANON_KEY`

Optional:

- `EXPO_PUBLIC_POKEMON_TCG_API_KEY` — from [Pokémon TCG API](https://dev.pokemontcg.io/) (higher rate limits).
- `EXPO_PUBLIC_USE_MOCK_CARD_SEARCH=true` / `EXPO_PUBLIC_USE_MOCK_PRICING=true` — avoid network for local tests.

## 2. Supabase: schema, RLS, and storage

1. In the Supabase SQL editor, run `supabase/schema.sql` (creates `profiles`, `cards`, `user_cards`, `price_history`, RLS, and storage policies).
2. In **Storage → New bucket**, create a **private** bucket named **`user-card-images`**.
3. Confirm **Authentication → Email** is enabled for email/password.
4. (Optional) **Authentication → Providers → Google** when you are ready; see `services/auth/googleSignInPlaceholder.ts` and the note on the login screen.

## 3. Run in development (Expo + Dev Client)

```bash
npx expo start
```

Use the **development build** (dev client) on a simulator or device, not only Expo Go, so behavior matches prebuild and native modules.

## 4. Native projects with **Expo prebuild** (Android & iOS)

This repo is configured for **Expo prebuild** so you can check in or regenerate `android/` and `ios/`.

Generate native directories (after `npm install`):

```bash
npx expo prebuild
```

This creates/updates the **`android`** and **`ios`** folders from `app.config.ts` and your app dependencies.

- Re-run prebuild when you add native modules or change native config.
- Add `google-services.json` / iOS Google config only when you wire Google sign-in or FCM, etc.

## 5. Android Studio and the `android` folder

1. Run `npx expo prebuild` (if `android/` is not present or you need a clean regen).
2. Open **Android Studio** → **Open** → select the **`android`** directory inside this project.
3. Let Gradle sync finish. Set **JDK 17** if prompted (Expo / RN typically expect a modern JDK).

### Run on Android Emulator

1. In Android Studio → **Device Manager**, create/start a virtual device.
2. From the project root:

   ```bash
   npx expo run:android
   ```

   Or start Metro separately (`npx expo start`) and run the app from Android Studio.

### Run on a physical Android device

1. Enable **Developer options** and **USB debugging** on the phone.
2. Connect via USB (or use wireless debugging).
3. Verify `adb devices` lists the device.
4. Run:

   ```bash
   npx expo run:android
   ```

Use the same LAN as your PC when testing Expo dev server / Metro.

## 6. iOS compatibility (later)

- Apple Silicon: open **`ios/CardVault.xcworkspace`** (or `.xcworkspace` generated by CocoaPods) in Xcode after `npx expo prebuild`.
- Install CocoaPods dependencies (`cd ios && pod install`) if not done automatically.
- Run **`npx expo run:ios`** or build from Xcode.
- Configure signing team + bundle id (`app.config.ts`: `ios.bundleIdentifier`) before shipping.

## 7. Project layout

```
CardVault/
  app/                  # Expo Router routes (auth, tabs, card detail)
  components/           # Reusable UI (Screen, list rows, inputs)
  hooks/                # useAuth, useCollection
  lib/                  # Supabase client, storage helpers, collection helpers
  services/
    cardSearch/         # Pokémon TCG API + mock
    pricing/            # Registry + mock pricing + condition multipliers
    scanner/            # Upload + placeholder identification
    auth/               # Google OAuth notes (placeholder)
  types/                # Shared TS types & DB row shapes
  supabase/schema.sql   # Source of truth for DB + RLS
  assets/               # App icons / splash (replace with production art)
```

## 8. Troubleshooting

- **`npx` / `node` not found**: Install Node from [nodejs.org](https://nodejs.org/) and reopen the terminal.
- **Empty env**: the app shows **Setup** until `EXPO_PUBLIC_SUPABASE_*` are set; restart Metro with `npx expo start -c`.
- **Storage upload errors**: ensure bucket **`user-card-images`** exists and RLS policies from `schema.sql` were applied.
- **Pokémon search failures**: try mock mode (`EXPO_PUBLIC_USE_MOCK_CARD_SEARCH=true`) or add an API key.
